# Xiaowen AutoResearch

Minimize time to valid evidence. Keep ordinary work outside this kernel.

## 1. Resolve authority

1. Read the applicable `AGENTS.md` chain and the directly used contract,
   manifest, config, or run record. They hold exact task values; this Skill
   cannot override higher authority.
2. Before a write, remote action, GPU run, protected access, or evidence seal,
   state the repository, branch, environment, scope, owner, and authority.
   Preserve unrelated and concurrent dirty work.
3. Treat reversible local work as pre-authorized only within its stated scope.
   Stop for destructive loss, paid/public/production action, authentication,
   permission expansion, protected access, or changes to scientific identity,
   budget, stop rule, or claim.
4. Stop on a decision-critical authority conflict. Unknown evidence remains
   `UNVERIFIED`; an engineering failure never supplies scientific authority.

## 2. Load only the active boundary

Default to Lite: one decision-complete owner, the user-visible task as the
capsule, and no coordination machinery. Use Managed only when a remote or
unattended process can outlive the turn, protected evidence will be accessed,
shared write state must change, a real external block must be scheduled, or a
confirmatory/publication decision needs physical independence.

- For a scientific contract, evidence, protected access, claim, or closure, load
  [research-integrity.md](references/research-integrity.md).
- For explicit opportunity/discovery work, also load
  [problem-space.md](references/problem-space.md).
- For Managed activation, a long job, external block, or final transition, load
  [orchestration.md](references/orchestration.md). Add
  [state-schema.md](references/state-schema.md) only when durable Controller
  state is touched.
- For a decision-changing knowledge handoff, load
  [research-map-maintenance.md](references/research-map-maintenance.md).

Load no other reference by default. Detailed commands and schemas belong to
their tools or cold references, not this hot path.

## 3. Freeze the evidence contract prospectively

Before the first evidence-bearing, protected, remote, or GPU effect, freeze in
one direct contract:

- question, hypothesis, estimand, lawful inputs, data/split/exposure boundary;
- primary metric, threshold or MPE, analysis, seeds, stop/action rule, and claim;
- strongest fair matched-cost baseline plus a mechanism-deletion control;
- code, config, data, model, environment, command, output, and run identity; and
- pessimistic decision-complete resource ceiling with bounded failure headroom.

Use `R0`--`R3` only as readiness shorthand. `R0` freezes the smallest lawful
decision and falsifier; `R1` makes the real carrier and fair baseline runnable
without utility; `R2` freezes the evidence-bearing identity and action table;
`R3` is eligible interpretation or claim. Apply fuller power, multiplicity,
baseline, and external-validity requirements only to confirmatory, superiority,
powered-negative, publication, or closure claims.

Use primary sources for definitions and decision-critical settings. Do not
claim novelty from incomplete neighbors. In FedFT/FedPEFT, rule out collapse to
centralized training, ordinary PEFT, simple adapter merge, budget differences,
or a weaker baseline before attributing a mechanism-specific contribution.

## 4. Keep reversible engineering in one owner

Keep one continuous Sol owner for formulation, contract freeze, pre-utility
engineering, real carrier, evidence return, and the final scientific decision.
Choose effort from the remaining work, not from a role label.

Before utility or protected access, repair path, argv, hash, dependency,
download, transport, permission, launcher, config, schema, grant, and carrier
constructability faults in that owner. These are ordinary progress: do not
create a governance-only terminal, independent review, new objective, ordinary
Controller lifecycle write, or user-rescue gate merely because one occurred.

Repair or rerun only under the unchanged scientific identity and cumulative
hard ceiling. If an unsafe carrier has produced no utility or protected access,
replace its `carrier_generation` inside the same scientific attempt. Before
release, replay the production entrypoint at zero utility, recompute identities
from actual bytes, and run access plus future-reader canaries.

Do not deliberately terminalize a reversible pre-utility defect. If the runtime
nevertheless emits `FINAL+NON_TERMINAL`, use the existing Controller v5 recovery
path without inventing another protocol. Transport, access, implementation, or
carrier failure is not a negative scientific result and cannot close an idea.

This E0 candidate keeps a continuous Sol owner and does not delegate to Luna;
Luna routing is a separate later experiment, not a release prerequisite.

## 5. Enforce the hard evidence boundary

- Keep public literature separate from candidate-protected outcomes. Public
  primary results may inform `R0`; they do not expose the candidate result.
- Use `strict_result_blind` only for a prospectively named independence need.
  Validate its safe tree and `operational_access` before dispatch; open only
  exact bound files and run exact helpers/argv. Missing identity blocks before
  bytes, and exposure invalidates that blind attempt.
- After utility or protected-outcome access, forbid outcome-conditioned rescue:
  do not change metric, subset, seed, stopping, carrier, baseline, budget,
  analysis, or claim to improve the conclusion. Apply the frozen action table.
- Preserve exact debit and the hard ceiling. A forecast miss below the ceiling
  is engineering information; exceeding the ceiling is forbidden.
- Bind evidence to exact run identity. Preserve raw outputs, failures,
  anomalies, and deviations before interpretation; immutable terminal checks
  and file digests cannot establish a scientific claim by themselves.
- Derive `completed -> contract-consistent -> evidence-eligible -> independently
  verified -> claim-accepted`. Report `FACT / INFERENCE / HYPOTHESIS /
  UNVERIFIED`, and keep claims no stronger than their evidence.
- Keep negative/null conclusions scoped. Missing sources, engineering failure,
  access failure, or an invalid carrier cannot become a field-wide `NO-GO`.

## 6. Require independence only where it changes validity

Use a physically distinct, eligible reviewer only for protected or confirmatory
interpretation, publication-facing claims, scientific closure, or a material
fairness/exposure judgment named prospectively. The producer cannot self-accept
such a decision. Ordinary exploration, implementation, repair, transport, and
launcher work do not need a separate standing role or session.

Independent review checks evidence and the frozen contract; it does not repair
the carrier, change authority, or rescue an observed outcome. Pro and same-model
review remain advisory and cannot supply missing evidence or permission.

## 7. Use Controller v5 only on its cold boundary

Load the orchestration reference and existing tooling only for Managed
activation, registered long jobs, genuine external blocks, or final evidence
transition. Controller coordinates ownership and durable state; it does not
interpret engineering details or relay them between standing roles.

Keep an internal engineering gap owned. A finite `BLOCKED` state requires a
genuine external fact or unavailable authority plus an observer, reopening
check, and deadline. A long job records its exact identity, one liveness point,
receipt path, check/cancel commands, and return mechanism, then releases the
interactive turn. Use the existing v5 terminal, callback, cursor, job, and
recovery semantics from the cold reference without reproducing them here.

For Lite work, finish when every named action is `DONE`, genuinely `BLOCKED`,
or receipt-backed `DELEGATED`. `DONE` for an idea requires scientific closure;
ordinary engineering completion is only progress toward evidence.

## 8. Review changes and report completion

Use the cheapest decision-complete local check first. Send broad refactors,
root-cause redesigns, or hard-boundary changes to the existing Pro conversation
as a fixed-commit review bundle; adjudicate its advice locally. Narrow,
reversible fixes may skip Pro. Never use reviewer agreement as authority.

After changes, run the narrowest relevant validation and report exact commands,
PASS/FAIL, remaining boundaries, impact, and rollback. Retain a workflow change
only when hard reliability is non-inferior and real research throughput or
operator cost improves; otherwise roll it back instead of adding prose.
